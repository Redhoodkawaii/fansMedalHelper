# GitHub Actions 每日报告

## 第一次启用

1. 将本次更新合并到仓库默认分支。打开 GitHub 仓库的 **Actions**，如果页面提示需手动为 fork 启用工作流，请点击启用。
2. 选择 **Daily Fans Medal Report → Run workflow**，选择默认分支并运行。在执行详情中点开 **Generate simulated daily report** 查看模拟等级、亲密度，以及观看、点赞、弹幕三项进度和估算积分。
3. 再运行一次，同一个北京时间自然日会显示跳过。工作流串行运行，并用 GitHub Actions 缓存记录当日完成。缓存过期、被清除或写入失败后可能重新生成模拟报告。GitHub 可能延迟执行定时任务，公开仓库连续 60 天无活动时也可能停用定时任务。

默认每天约北京时间 20:10 运行。模拟任务无需 Secret，只读访问 GitHub 仓库。每次成功运行的公开日志只有固定模拟数据。旧版 **Sync Fork** 可能将默认分支更新为直接上游的代码，使用前请先核对工作流变更。

## 使用自己的勋章数据

在 B 站官方客户端登录，由你完成登录验证。打开装扮中心的粉丝勋章页面，选一个主播，记录等级和亲密度。在直播间粉丝团任务面板查看当日计入进度的观看分钟数、点赞次数和有效弹幕条数。任一项不可见时填 `null`。在本项目目录创建 `medal-snapshot.json`，用你看到的数值替换下面的示例。

```json
{"level": 12, "intimacy": 830, "watch_minutes": 45, "likes": 60, "danmaku": 4}
```

用 Python 3.11 运行 `python run_actions.py --snapshot medal-snapshot.json`。报告保存在 `daily-reports/manual-日期.json`，终端只显示生成结果。同日重复运行会保留首份报告。数值文件和报告目录已列入 Git 忽略规则，请留在本机。若已有旧版 `BILI_ACCESS_KEY`，合并后可在 **Settings → Secrets and variables → Actions** 删除。当前工作流无需提供 Cookie、登录令牌或账号授权。

## 截至 2026-11-18 查到的规则

本项目按直播间粉丝团升级任务的现行参考口径估算奖励。你提供的门槛与 2026 年 5 月的社区记录一致，实际进度和结算以对应直播间的任务面板为准。尚未找到确认这三项门槛的 B 站公开公告。[2026 年社区记录](https://github.com/NoneOfNothing/Bilibili_live_sc_get/blob/main/docs/B站粉丝牌机制.md)

| 任务 | 每次计入 | 单项每日上限 |
| --- | --- | --- |
| 观看直播 | 每满 15 分钟估算 1 点 | 10 点 |
| 点赞 | 每满 30 次估算 1 点 | 10 点 |
| 发弹幕 | 每 1 条有效弹幕估算 1 点 | 10 点 |

2025 年官方改版公告记载的每 5 分钟 6 点是当时的规则，报告采用上表的粉丝团任务口径。投币和付费项目的当前收益以官方客户端为准。[2025 年官方改版公告](https://www.bilibili.com/opus/1100097465625870441)
