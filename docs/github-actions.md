# GitHub Actions 每日运行

工作流每天约北京时间／新加坡时间 20:10 启动，也可在 Actions → Daily Fans Medal Helper → Run workflow 手动启动。电脑关机不影响 GitHub 云端任务。

## 仅有一个必需的 Secret

在本仓库 Settings → Secrets and variables → Actions → New repository secret 中填写：

- Name：`BILI_ACCESS_KEY`
- Secret：你自己安全取得的 B 站 app `access_key`（不是密码，也不是浏览器 Cookie）。

凭证只能在 GitHub 的 Secret 输入框添加，不要发到聊天、Issue、提交、配置文件或截图中。当前连接工具不能替你读取或管理 Secrets。请自行确认登录工具来源；不要向不明网站提供凭证。

保存后先手动运行一次。尚未添加 Secret 时任务会明确失败，不会向 B 站发送请求。

## 默认行为与限制

- 读取示例配置，但只使用 Secret 中的一个账号；禁用程序内部定时器，运行一次后退出。
- 仅处理直播间 https://live.bilibili.com/7222865 对应主播 UID `243265104` 的粉丝牌，不处理其他主播；若以后清空或填错 UID 格式则停止运行。
- 对指定粉丝牌发送一条原项目随机弹幕（[花] 或 [比心]），弹幕间隔配置为 60 秒。
- 观看目标为指定牌子 30 分钟，使用原项目的顺序模式，间隔 60 秒；观看总时限 75 分钟，牌子多时可能无法全部完成。
- 点赞、应援团签到、活动签到、自动换牌和第三方通知默认关闭。已停用下架的直播区签到接口，避免错误码 10006 导致任务失败。
- 整个任务最长 100 分钟；不上传日志或配置文件。公开输出仅保留粗略成功／失败状态、固定接口类别与数字错误码，原始账号与 API 错误详情被隐藏。
- 成功状态只表示程序没有报告错误，不代表 B 站已结算亲密度；接口失效、登录过期和云端 IP 风控仍可能导致失败。
- 所有运行使用只读仓库权限，检出步骤不保存 GitHub 凭证，登录凭证只传给最终运行步骤。
- 上游同步改为手动操作，来源为直接上游 `xiaofeiTM233/fansMedalHelper`；同步后须重新检查涉及凭证的代码。
- GitHub 定时任务可能延迟；公开仓库连续 60 天无活动时定时任务可能自动停用。不通过自动提交绕过该限制。

修改默认设置可编辑 `run_actions.py`。不要把凭证写进该文件。定时表达式位于 `.github/workflows/daily.yml`，使用 UTC。
